# Архитектура VANTAGE

Карта системы: что где лежит, какое решение в каждом модуле главное и
какое у него честное ограничение. Читается за десять минут, покрывает
весь код.

---

## Поток данных

```
   STAC (Planetary Computer)
        │  catalog.py
        ▼
   ┌────────────────────────────────────────────────┐
   │  ФИЗИКА: пять независимых признаков             │
   │                                                 │
   │  raster.py  → indices.py   NDVI, BSI, PMLI      │  оптика
   │  sar.py                    нестабильность S1    │  радар
   │  thermal.py                аномалия Landsat     │  тепло
   └────────────────────────────────────────────────┘
        │
        ▼  change.py       поиск необратимого разрыва во времени
        ▼  candidates.py   векторизация в полигоны + дата возникновения
        ▼  context.py      отсев по OSM: тысячи → десятки
        ▼  chips.py        пары чипов «до / после»
        ▼  model/          сиамская сеть: что ИЗМЕНИЛОСЬ, а не что видно
        ▼  explain.py      доказательная цепочка вместо вердикта
        ▼  verify.py       тайлы 0.7 м, несколько провайдеров
        │
        ├──► money.py + methane.py   ущерб как диапазон P10–P90
        ├──► risk.py                 прогноз появления новых
        ├──► removal.py              контроль исполнения
        ├──► act.py                  черновик → подтверждение человеком
        │
        ▼  signals.py      радар, тепло и полимеры по найденным объектам
        ▼  pipeline.py     плитки, склейка на стыках, артефакты
        ▼  orchestrate.py  сквозной прогон: снимки → файлы карты
        │
   ┌────┴─────┬──────────┬──────────┐
   │   api/   │   bot/   │   web/   │
   │  роли    │ жители   │ офлайн   │
   └──────────┴──────────┴──────────┘
```

## Модули

### Данные и физика

| Модуль | Главное решение | Честное ограничение |
|---|---|---|
| `env.py` | окружение GDAL готовится до первого гео-импорта | без этого на пути с казахскими буквами не читается ни один снимок |
| `catalog.py` | STAC вместо скачивания: читаем окна по HTTP-range | зависимость от доступности Planetary Computer |
| `raster.py` | медиана по месяцу, а не единичный снимок | SCL пропускает тонкую облачность |
| `indices.py` | поправка Baseline 04.00 | без неё разрыв 25.01.2022 во всём AOI |
| `sar.py` | прокси когерентности по амплитуде RTC | не строгая интерферометрия по фазе |
| `thermal.py` | фон медианой в кольце, а не средним по сцене | летом сигнал тонет в солнечном нагреве |
| `signals.py` | радар и тепло считаются по найденным объектам, а не по всем пикселям | радар идёт блоками 5×5 км: куб 20×20 км за восемь лет весит гигабайты |

### Детекция

| Модуль | Главное решение | Честное ограничение |
|---|---|---|
| `change.py` | гармоники снимают сезонность → пашня отсеивается автоматически | две гармоники: три начали бы подгоняться под шум |
| `candidates.py` | атрибуты медианой; сопоставление полигонов с метками по координате | объекты < 30–50 м² не разрешаются |
| `context.py` | шесть правил отсева, каждый кандидат получает **причину** | OSM неполон в пригороде |
| `chips.py` | статистика нормировки только по обучающей части | при малой выборке она сама шумит |
| `model/` | сиамская схема: учим изменение, а не внешний вид | нужна ручная разметка 200–400 фрагментов |
| `explain.py` | согласие признаков (среднее), а не сила одного (максимум) | шкалы нормировки заданы по физике, не по данным |
| `verify.py` | несколько провайдеров, отказ одного не останавливает проход | выборочно, по лимиту `max_candidates` |

### Экономика и действие

| Модуль | Главное решение | Честное ограничение |
|---|---|---|
| `money.py` | Монте-Карло по треугольным распределениям → P10/P50/P90; `portfolio()` — интервал по списку целиком | сильнее всего итог двигает тариф вывоза, ρ = 0,82 |
| `methane.py` | IPCC FOD, GWP на 20 лет | разовое захоронение вместо постепенного роста |
| `risk.py` | **валидация по времени**, не случайная | метрика ниже, чем при случайном разбиении, — и честнее |
| `removal.py` | тепло видит сквозь присыпку → отдельный статус | без теплового признака уверенность режется до 0.7 |
| `act.py` | черновик, пока человек не подтвердил именем и должностью | не заменяет выездную проверку |

### Сервисы

| Модуль | Главное решение | Честное ограничение |
|---|---|---|
| `api/` | 404 вместо 403; оператор не подтверждает акты | bearer-токены из окружения, не полноценный IdP |
| `bot/` | ценность в **несовпадениях**: житель видит то, чего не видит спутник | публичный бот требует антиспама |
| `web/` | свой рендерер: ни одного внешнего ресурса | нет растровой подложки, только сетка координат |

## Три сквозных принципа

**Ни одного магического числа в коде.** Любой порог живёт в
`config/default.yaml` и имеет имя. Эксперимент — это правка YAML,
а не правка кода.

**У каждой цифры есть происхождение.** В `config/economics_astana.yaml`
каждый параметр помечен как `source` (документ), `derived` (формула
вывода) или `estimate` (инженерная оценка). `vantage doctor` падает,
если остался хоть один `TODO`, и отдельно перечисляет оценочные величины.

**Метры считаются в метрах.** Любое расстояние, площадь и буфер — только
в UTM 42N. Смешение градусов и метров не падает с ошибкой, оно тихо даёт
неправильный ответ.

## Артефакты прогона

Всё в `outputs/`. Сервис и карта читают только их и ничего не знают
про пайплайн.

| Файл | Что внутри |
|---|---|
| `scenes.json` | сколько сцен нашлось по области и периоду |
| `candidates.geojson` | объекты: геометрия, дата, признаки, деньги, статья |
| `risk_private.geojson` | точная сетка риска для службы |
| `risk_public.geojson` | зоны риска классами, растворённые, без точных вероятностей |
| `story.json` | сценарий демонстрации: порядок сцен и реплики |
| `run.json` | что, когда, сколько заняло |
| `access.log` | журнал обращений к адресным данным |
| `citizen_reports.jsonl` | сообщения жителей |
| `acts/` | сформированные акты |

## Почему нет базы данных

Объектов десятки, а не миллионы. Запись идёт пакетом раз в сутки, а не
построчно. GeoJSON и JSONL читаются любым инструментом, версионируются
и не требуют поднимать сервер перед демонстрацией.

База появится, когда появится второй регион и одновременная запись —
и тогда это будет обоснованное решение, а не оверинжиниринг из
привычки.

## Что запускать

```powershell
vantage info                  # что сконфигурировано
vantage doctor --network      # готовность к сдаче + чтение снимков из облака
vantage scenes                # сколько данных доступно
vantage money 5000 --sensitivity
vantage sample                # синтетика для отладки интерфейса
vantage web                   # карта на localhost:8080

# сквозной прогон по своей области; плитки кешируются, прерывание безопасно
vantage run --bbox 71.37,51.12,71.66,51.30 --name astana_north
```

Порядок внутри прогона имеет одну неочевидную зависимость: разметка и
обучение идут по **сырым** кандидатам, до контекстного отсева. Отсев
вычитает известные полигоны ТБО — то есть ровно те объекты, которые
служат положительными примерами.
