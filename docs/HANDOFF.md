## Что осталось и почему

### Требует сети — доделать, когда интернет стабилен

**Радар и доверификация.** Обе ветки написаны, проверены на живых данных и
работают, но в финальном прогоне не отработали: интернет пропал ровно на
них. В карточке объекта радар честно пишет «нет данных».

```powershell
python scripts/finish_ring.py          # доберёт радар и доверификацию
```

**Контроль устранения.** `posthistory.py` собирает ряды после даты разрыва,
`removal.py` по ним отвечает «убрали или засыпали». Первый запуск упал:
он тянул 198 км² одним куском, и сеть легла на девятнадцатой минуте из
двадцати. Переделано на блоки 5×5 км с кешем на диске — повторный запуск
доберёт только недостающее.

```powershell
python scripts/check_removal.py        # блоками, с кешем, можно прерывать
```

Карта уже готова принять результат: статус показывается в реестре и в
карточке, сортировка «сначала подозрение на присыпку» стоит по умолчанию.
Без данных колонка просто не появляется.

**Две плитки из 25** не дошли по сети. `scripts/run_ring.py` доберёт их из
кеша, пересчитав только недостающие.

### Требует решения человека

**Telegram-бот.** Код готов, страница контура есть, имени нет. Кнопка и QR
появляются после:

```powershell
python scripts/make_bot_qr.py @имя_бота
cd web-next; npm run build
```

Имя не подставлено заранее намеренно: выдуманная ссылка на защите
открывается в пустоту.

**Ручная разметка.** Это единственный путь обучить сеть, и он упирается в
человека, а не в код. Положительных примеров из OpenStreetMap не набирается
в принципе: внутри существующего полигона ТБО детектор изменений ничего не
находит — там и в 2018 году была голая поверхность. На кольце автоматически
разметилось 17 объектов из 607, все семнадцать отрицательные.

```powershell
python scripts/export_chips.py 200     # уже сделано, 200 пар лежат в сборке
# открыть label.html, пройти очередь, скачать labels.json
python scripts/train_from_labels.py labels.json
```

Пока сеть не обучена, карта показывает согласие пяти физических признаков и
подписывает это именно так, а не выдаёт за вероятность.

### Не начато

- **Зрительная модель подключена, но по умолчанию молчит.** Клиент есть
  ([`vlm.py`](../src/vantage/vlm.py)), ответ приходит по схеме. Без
  `ANTHROPIC_API_KEY` `build_verifier()` возвращает `None`, и прогон идёт
  без неё — отсутствие ключа не должно ронять всё остальное.
- **API не развёрнут** — осознанно: он отдаёт точные координаты и суммы.
  Кнопка акта на карте печатает документ локально через браузер.
- **Обращения жителей на карте** — появятся после развёртывания бота.

## Ловушка окружения, стоившая трёх прогонов

Если снимки перестали читаться, а на вид «плохая сеть» — сначала сюда.

**Признак.** Каждое чтение COG по HTTPS отваливается с `HTTP error code: 0`
или `UnicodeDecodeError` в `rasterio/_err.pyx`. При этом `requests` те же
самые ссылки скачивает без единой ошибки — у него свои сертификаты и своя
реализация TLS, и именно это сбивает с толку.

**Причина.** Путь проекта содержит `Жұмыс үстелі`. Букв `ұ` и `ү` нет в
кодовой странице 1251, а её применяет schannel, открывая файл сертификатов
по указанию GDAL. Файл не открывается — HTTPS не работает.

**Защита и как она себя отключила.** [`env.py`](../src/vantage/env.py)
кладёт ASCII-копию сертификатов в `C:\ProgramDataantage\`, если путь
непредставим. Представимость проверялась через
`locale.getpreferredencoding`. После перехода проекта на `PYTHONUTF8=1`
Python стал отвечать на этот вопрос «UTF-8» — он говорит о себе, а не о
системе. Путь с `ұ` в UTF-8 представим, проверка вернула True, копия
перестала создаваться. Собственный режим совместимости отключил защиту,
написанную ровно против этой поломки.

Теперь кодовая страница спрашивается у Windows через `GetACP`, и это
закреплено тестами: [`tests/test_env_ca.py`](../tests/test_env_ca.py).

**Проверить за минуту:**

```powershell
.venv\Scripts\python.exe -c "import os; from vantage.env import ansi_encodable; p=os.environ['GDAL_CURL_CA_BUNDLE']; print(p, ansi_encodable(p))"
```

Путь обязан быть `C:\ProgramDataantageantage_cacert.pem`, ответ —
`True`. Если там путь внутри `.venv`, значит `pyogrio` затёр переменную
после нашей настройки, и чтение снимков работать не будет.

**Второе место той же природы.** `pyogrio` выставляет
`GDAL_CURL_CA_BUNDLE` при импорте, безусловно, затирая наше значение.
Поэтому `configure()` импортирует его явно и переустанавливает сертификаты
после. Полагаться на то, что чужая библиотека не тронет переменную
окружения, здесь уже нельзя.

## Как всё запустить с нуля

```powershell
$env:PYTHONUTF8 = "1"
pip install -e ".[dev,ml,service]"

vantage doctor --network               # проверит и чтение снимков из облака
vantage run --bbox 71.37,51.12,71.66,51.30 --name astana_north --outputs outputs_real
python scripts/make_patrol.py 20
python scripts/check_removal.py
vantage web                            # соберёт сайт и поднимет на :8080
```

Первая команда обязательна на новой машине: она ловит поломку, при которой
STAC отвечает, а пиксели не читаются. Подробности — в `vantage/env.py`.
