## Блокирует всё остальное

### 1. Разметка обучающей выборки

**Статус:** механизм готов, данных нет.
**Файлы:** [`src/vantage/labels.py`](../src/vantage/labels.py)

Часть меток берётся из OpenStreetMap автоматически: полигоны ТБО как
положительные примеры, карьеры и стройки как трудные отрицательные.
Остальное надо смотреть глазами.

```python
from vantage.aoi import AOI
from vantage.config import load_settings
from vantage.labels import harvest_labels, manual_queue, class_balance

settings = load_settings()
aoi = AOI.from_settings(settings)
labelled, report = harvest_labels(aoi, settings, candidates)
print(report.to_text())
print(class_balance(labelled))

queue = manual_queue(labelled, limit=100)   # что смотреть руками
```

**Что нужно:** пройти очередь `manual_queue`, проставить `label` 0 или 1.
Инструмента для разметки нет — можно смотреть в QGIS или в браузере по
координатам. **Написать простую страницу для разметки было бы полезно:
показать чип, две кнопки, следующий.**

## Модули, готовые, но не соединённые в цепочку

### 3. SAR и тепло не подключены к детектору

**Статус:** посчитать признаки умеем, в решение они не входят.
**Файлы:** [`sar.py`](../src/vantage/sar.py), [`thermal.py`](../src/vantage/thermal.py),
[`change.py`](../src/vantage/change.py)

`change.detect()` использует только NDVI и BSI. Радарная нестабильность
и тепловая аномалия считаются отдельно и попадают только в панель
объяснимости. **Нужно завести их в общее решение** — либо как
дополнительные условия в `detect()`, либо как каналы чипа для сети.

### 4. Доверификация не вызывается из пайплайна

**Статус:** модуль работает, в прогоне не участвует.
**Файлы:** [`verify.py`](../src/vantage/verify.py)

`verify_candidates()` тестируется на заглушках. По-настоящему тайлы
никто не тянул. **Нужно:** вызвать на реальных кандидатах, посмотреть,
что отдают провайдеры, и проверить, работает ли текстурный анализ на
настоящих снимках, а не на синтетических квадратиках.

### 5. Контроль устранения не встроен

**Статус:** логика готова, входных данных нет.
**Файлы:** [`removal.py`](../src/vantage/removal.py)

`assess_removal()` ждёт ряды наблюдений после даты обнаружения.
Пайплайн их не собирает. **Нужно:** после детекции вырезать
пост-историю по каждому объекту и прогнать через модуль.

### 6. Зрительная модель не подключена

**Статус:** интерфейс есть, реализации нет.
**Файлы:** [`verify.py`](../src/vantage/verify.py), класс `VlmVerifier`

Протокол описан, промпт написан, тесты на заглушке проходят.
Настоящего клиента к какой-либо модели нет. **Нужно:** реализовать
класс с методом `verify(image, prompt) -> dict` и передать в
`verify_candidates(vlm=...)`.

## Известные технические долги

- **`pipeline.step_risk`** вызывается только из тестов; в `vantage run`
  ветка риска не встроена.
- **Чипы не сохраняются между запусками.** `ChipDataset.save()` есть,
  пайплайн им не пользуется — при переобучении всё режется заново.
- **Нет ретраев к STAC.** Один таймаут роняет шаг целиком.
- **`money.assess()` вызывается по объекту в цикле.** На десятках это
  мгновенно, на тысячах будет заметно; тогда понадобится векторизация.
- **Тайловый кеш в браузере ограничен 4000 записями** и чистится
  грубо, с начала. Для области Астаны хватает, для страны — нет.
