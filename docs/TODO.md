## Блокирует всё остальное

### 1. Разметка обучающей выборки

**Статус:** автоматическая часть работает в прогоне, ручной нет.
**Файлы:** [`src/vantage/labels.py`](../src/vantage/labels.py)

Часть меток берётся из OpenStreetMap автоматически: полигоны ТБО как
положительные примеры, карьеры и стройки как трудные отрицательные.
Остальное надо смотреть глазами.

```python
from vantage.aoi import AOI
from vantage.config import load_settings
from vantage.labels import harvest_labels, manual_queue, class_balance

settings = load_settings()
aoi = AOI.from_settings(settings)
labelled, report = harvest_labels(aoi, settings, candidates)
print(report.to_text())
print(class_balance(labelled))

queue = manual_queue(labelled, limit=100)   # что смотреть руками
```

Разметка вызывается из прогона автоматически ([`orchestrate.finish_run`](../src/vantage/orchestrate.py)),
и вот важная тонкость порядка: она идёт по **сырым** кандидатам, до
контекстного отсева. Отсев вычитает из списка известные полигоны ТБО —
то есть ровно те объекты, которые служат положительными примерами.
Разметить после него означало бы получить выборку без единого
положительного класса.

Если каждого класса набралось меньше пяти примеров, сеть не обучается, и
карта показывает прочерк вместо уверенности. Это сознательно: выдуманное
число хуже пустой ячейки.

**Главное, что выяснил первый настоящий прогон: положительных примеров из
OSM не набирается вообще — ноль.** И это не сбой, а следствие метода.
Внутри существующего полигона ТБО детектор изменений ничего не находит:
там и в 2018 году была голая поверхность, разрыва нет. Нет разрыва — нет
кандидата — нечему ставить метку «свалка». На кольце 20×20 км с шестью
полигонами ТБО в OSM (107, 79, 43, 42, 26 и 21 га) автоматически
разметилось 16 объектов из 420, и все шестнадцать — трудные отрицательные.

Значит, вариантов ровно три, и первые два — работа руками:

1. пройти `manual_queue` глазами (см. ниже);
2. размечать не кандидатов, а **края** полигонов ТБО — там, где полигон
   рос в течение периода, разрыв есть; таких мест единицы;
3. не обучать сеть вовсе и показывать согласие пяти физических признаков.

Третье уже сделано и работает: [`explain.attach_evidence`](../src/vantage/explain.py)
добавляет `evidence_score` и `n_agreeing`, карта показывает их со звёздочкой
и подписью «оценка по признакам, не моделью». Это слабее модели, зато
объясняется без слова «нейросеть» и есть всегда.

**Что нужно:** пройти очередь `manual_queue`, проставить `label` 0 или 1.
Инструмента для разметки нет — можно смотреть в QGIS или в браузере по
координатам. **Написать простую страницу для разметки было бы полезно:
показать чип, две кнопки, следующий.**

### 2. Настоящий прогон вместо синтетики — СДЕЛАНО

**Статус:** работает, запускается одной командой.
**Файлы:** [`orchestrate.py`](../src/vantage/orchestrate.py),
[`pipeline.py`](../src/vantage/pipeline.py)

```powershell
vantage run --bbox 71.37,51.12,71.66,51.30 --name astana_north
```

Область идёт плитками с перекрытием 800 м; каждая пишет результат в
`outputs/tiles/` и при повторе берётся из кеша, включая пустые. Объекты,
разрезанные границей плитки, склеиваются обратно
([`merge_across_tiles`](../src/vantage/candidates.py)): половинки по 600 м²
иначе обе провалили бы порог минимальной площади в 900 м².

Скорость измерена, а не оценена: **около 6 с на км²** за восемь лет.
Плитка 22 км² — 442 даты, 61 месячный композит, 98,4% валидных пикселей,
две с половиной минуты. Область из конфигурации — порядка восьми часов.

Попутно чинилось три вещи, каждая из которых блокировала прогон целиком:

**Сертификаты.** `pyogrio` отдавал GDAL путь к certifi внутри проекта, а в
пути есть `ұ` и `ү`, которых нет в кодовой странице Windows. schannel
отбрасывал файл сертификатов, и ни один COG по HTTPS не открывался. Ошибку
не было видно: rasterio падал с `UnicodeDecodeError`, пытаясь прочитать
сообщение GDAL. Лечит [`env.py`](../src/vantage/env.py).

**Типы.** `catalog.search_*` возвращал компактный `SceneRef`, а
`raster.load_s2_stack` передавал его в `odc.stac.load`, которому нужен
`pystac.Item`. То есть ветка растров не могла отработать в принципе.
Добавлен `StacCatalog.sentinel2_items`.

**Хвост ряда.** Первый прогон вернул 29 кандидатов, у 25 из них дата
разрыва — последний месяц периода. Разбор в
[`test_observability.py`](../tests/test_observability.py); коротко:
проверка на необратимость смотрит вперёд на 18 месяцев, и в конце ряда ей
некуда смотреть. Разрывы, после которых не осталось окна наблюдений,
теперь исключаются **из области поиска**, а не отбрасываются постфактум —
иначе пиксель терялся целиком вместе с настоящей находкой в середине ряда.

**Что осталось:** прогон по всей области из конфигурации (восемь часов) и
распараллеливание по плиткам — сейчас они идут последовательно.

## Модули, готовые, но не соединённые в цепочку

### 3. SAR и тепло — подключены к объектам, не к детектору

**Статус:** признаки считаются и доезжают до карты; в решение детектора
по-прежнему не входят.
**Файлы:** [`signals.py`](../src/vantage/signals.py), [`sar.py`](../src/vantage/sar.py),
[`thermal.py`](../src/vantage/thermal.py)

`attach_signals()` досчитывает `sar_incoherence` и `thermal_anomaly` по
уже найденным объектам, `pmli_response` достаётся из нарезанных чипов
бесплатно. Панель доказательств на карте перестала быть пустой на
настоящих данных — раньше пять признаков были только у синтетики.

Отдельным проходом, а не внутри плиточного прогона, потому что это три
разные коллекции с разным разрешением и разной сеткой дат: тянуть их
вместе означало бы утроить самый дорогой шаг ради признаков, которые
нужны десяткам объектов, а не миллионам пикселей. Радар идёт блоками
5×5 км — куб 20×20 км за восемь лет в двух поляризациях весит около
четырёх гигабайт.

Заодно нашлось расхождение, которое портило панель: шкала радарного
признака была задана дважды и по-разному — `sar.py` считал полной шкалой
3 дБ, а `explain.py` и карта делили на 0.50. Признак показывался вшестеро
сильнее, чем он есть. Теперь шкалы берутся из модулей, которые эти
величины считают, и едут на карту вместе с данными (`story.signal_scales`).

**Что осталось:** завести признаки в само решение `change.detect()` —
либо дополнительными условиями, либо каналами чипа.

## Известные технические долги

- **`pipeline.step_risk`** вызывается только из тестов; в `vantage run`
  ветка риска не встроена.
- **Чипы не сохраняются между запусками.** `ChipDataset.save()` есть,
  пайплайн им не пользуется — при переобучении всё режется заново.
- **Нет ретраев к STAC.** Один таймаут роняет шаг целиком.
- **`money.assess()` вызывается по объекту в цикле.** На десятках это
  мгновенно, на тысячах будет заметно; тогда понадобится векторизация.
- **Тайловый кеш в браузере ограничен 4000 записями** и чистится
  грубо, с начала. Для области Астаны хватает, для страны — нет.
