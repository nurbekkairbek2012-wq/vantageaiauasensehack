# Развёртывание

Три части системы разворачиваются по-разному, потому что у них разные
требования. Ниже — что делать по шагам.

| Что | Куда | Кто может сделать |
|---|---|---|
| Карта | GitHub Pages | автоматически, нужен один клик в настройках |
| Бот | Fly.io / Railway | нужен токен от @BotFather |
| API | Fly.io / Railway | нужно решение о публикации адресных данных |

---

## 1. Карта на GitHub Pages

**Что уже сделано:** workflow `.github/workflows/pages.yml` собирает и
публикует карту при каждом пуше в `main`.

**Что нужно сделать вам — один раз, две минуты:**

1. Открыть репозиторий на GitHub → **Settings** → **Pages**
2. В разделе **Build and deployment**, поле **Source**, выбрать
   **GitHub Actions** (не «Deploy from a branch»)
3. Сохранить

После этого зайти во вкладку **Actions**, найти запуск
«Публикация карты на GitHub Pages» и дождаться зелёной галочки.
Ссылка появится там же и будет вида:

```
https://k41270075-stack.github.io/hakathon/
```

### Какие данные попадут на карту

Workflow смотрит папку `map-data/` в корне репозитория:

- **папка есть и не пуста** — публикуются данные настоящего прогона;
- **папки нет** — генерируется синтетика, и карта сама показывает
  красную полосу «синтетические данные», потому что в файлах стоит
  флаг `is_demo`.

Чтобы выложить настоящий прогон:

```powershell
vantage run                    # или потайлово через Python API
mkdir map-data
copy outputs\candidates.geojson  map-data\
copy outputs\risk_public.geojson map-data\
copy outputs\story.json          map-data\
git add map-data
git commit -m "data: результаты прогона по Астане"
git push
```

Карта пересоберётся сама.

> Синтетику в `map-data/` класть нельзя. Смысл папки именно в том,
> что её содержимое — результат реального прогона.

## 2. Telegram-бот

### Шаг 1. Создать бота — только вы

1. Открыть Telegram, найти **@BotFather**
2. Отправить `/newbot`
3. Придумать имя (например `VANTAGE Астана`) и username
   (например `vantage_astana_bot` — должен заканчиваться на `bot`)
4. BotFather пришлёт токен вида `7123456789:AAF...` — **это пароль,
   никому не показывайте и не коммитьте в репозиторий**

### Шаг 2. Узнать свой chat_id

Нужен, чтобы бот присылал вам оповещения о новых объектах.
Напишите боту **@userinfobot** — он ответит вашим числовым id.

### Шаг 3. Проверить локально

```powershell
cd vantage
$env:PYTHONUTF8 = "1"
$env:VANTAGE_BOT_TOKEN = "токен от BotFather"
$env:VANTAGE_BOT_SALT = "любая длинная случайная строка"
$env:VANTAGE_BOT_SUBSCRIBERS = "ваш chat_id"
.venv\Scripts\python.exe -m vantage.bot
```

Напишите боту `/start` — он должен ответить. Работает, пока открыто окно.

### Шаг 4. Поднять на сервере

Локальный запуск умирает вместе с ноутбуком. Для постоянной работы:

```bash
# один раз: установить fly.io CLI и войти
fly auth login

cd deploy
fly launch --no-deploy --name vantage-bot

fly secrets set VANTAGE_BOT_TOKEN="токен"
fly secrets set VANTAGE_BOT_SALT="случайная строка"
fly secrets set VANTAGE_BOT_SUBSCRIBERS="ваш chat_id"

fly deploy
fly logs          # убедиться, что бот запустился
```

**Почему Fly, а не бесплатный веб-хостинг.** Большинство бесплатных
платформ усыпляют контейнер, если в него нет входящих HTTP-запросов.
Бот работает через long polling: он сам ходит в Telegram за
обновлениями и входящих запросов не получает вообще — то есть
засыпает через несколько минут после деплоя и больше не отвечает.

**Railway** подходит так же: создать проект из репозитория, указать
`deploy/Dockerfile`, target `bot`, задать те же три переменные.

### Что бот умеет сразу

- `/start`, `/help`, `/stats`
- принимает геолокацию и фото от жителей
- сверяет точку с найденными объектами: совпало — подтверждение,
  не совпало — новый объект, которого спутник не увидел
- рассылает оповещения подписчикам
- ограничивает спам: 10 сообщений в сутки, 30 секунд между ними
- не хранит идентификатор отправителя, только хеш с солью

## 3. API (опционально, подумайте дважды)

API отдаёт **точные координаты и суммы ущерба** — адресные данные.
Публиковать его в интернет до защиты незачем: жюри смотрит карту и
репозиторий, а адресные данные в открытом доступе создают ровно ту
проблему, от которой мы защищались ролевым доступом.

Если всё же нужно:

```bash
cd deploy
fly launch --no-deploy --name vantage-api --dockerfile Dockerfile
fly secrets set VANTAGE_API_TOKENS="длинный-случайный-токен:akimat"
fly deploy --build-target api
```

Токены должны быть длинными и случайными. Не `test123`.
