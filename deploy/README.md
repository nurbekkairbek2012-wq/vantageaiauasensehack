# Развёртывание

Три части системы разворачиваются по-разному, потому что у них разные
требования. Ниже — что делать по шагам.

| Что | Куда | Что нужно от вас |
|---|---|---|
| Сайт | Vercel | аккаунт GitHub, пять минут |
| Бот | Fly.io / Railway | токен от @BotFather |
| API | Fly.io / Railway | решение о публикации адресных данных |

**Порядок важен.** Сайт первым: он работает сам по себе, без бота и без
API. Бот вторым, и у него две половины — имя, которое надо вшить в сайт, и
процесс, который надо где-то держать. API последним, если вообще.

---

## 1. Сайт на Vercel

Сборка описана в [`vercel.json`](../vercel.json) в корне репозитория:
команда сборки, папка результата, заголовки кеширования и CSP. Настраивать
в интерфейсе Vercel ничего не нужно — он прочитает файл сам.

1. Зайти на **vercel.com**, войти через GitHub.
2. **Add New → Project**, выбрать репозиторий `hakathon`, **Import**.
3. Root Directory оставить **корнем репозитория** — не `web-next`.
   `vercel.json` лежит в корне и сам заходит в `web-next`; если указать
   подпапку, Vercel не найдёт файл и соберёт не то.
4. Framework Preset — **Other**. Настройки сборки не трогать: значения из
   `vercel.json` перекрывают то, что показано в форме.
5. Переменные окружения — **никаких**. Сайт статический, ключей у него нет.
6. **Deploy**.

Сборка занимает около минуты. Дальше каждый пуш в `main` пересобирает сайт
сам, отдельно ходить в Vercel не надо.

### Что попадает на сайт

Данные лежат в `web-next/public/data/` и **закоммичены в репозиторий** —
десять файлов, включая результаты кольцевого прогона по Астане. Пересборка
на Vercel их не пересчитывает и не может: спутниковые снимки тянутся часами
и требуют геостека, которого в сборочном контейнере нет.

Поэтому обновление данных — это обычный коммит:

```powershell
vantage run --bbox 71.37,51.12,71.66,51.30 --name astana_north
# результаты автоматически ложатся в web-next/public/data/
git add web-next/public/data
git commit -m "data: результаты прогона по Астане"
git push
```

Если в файлах стоит флаг `is_demo`, сайт сам показывает красную полосу
«синтетические данные». Снимать её вручную нечем — она следует из данных.

### Проверить после деплоя

**Сначала — одной командой:**

```powershell
python scripts/check_live.py                 # адрес по умолчанию
python scripts/check_live.py https://другой.адрес
```

Скрипт проверяет не «отвечает ли сервер», а пришёл ли **наш** сайт:
имя продукта в HTML, все семь страниц, данные как JSON, число объектов
совпадает с локальной выгрузкой.

- [ ] Открываются все семь страниц: `/`, `/map`, `/economy`, `/timelapse`,
      `/forecast`, `/citizen`, `/label`
- [ ] На карте видны объекты, а не пустой серый прямоугольник
- [ ] Красной полосы «синтетические данные» **нет**
- [ ] Кнопка «Черновик акта» открывает окно печати с одним объектом,
      а не со всей страницей
- [ ] Всё это с телефона, а не только с ноутбука

### Если вместо сайта страница входа в Vercel

Так было 24 августа, и заметили это не мы: у проекта включена **защита
развёртывания**. Мы залогинены в Vercel — у нас ссылка открывается
всегда, — а посторонний упирается в стену авторизации. Проверить это из
своего браузера невозможно в принципе.

Чинится в одном месте: **Vercel → Project → Settings → Deployment
Protection → Vercel Authentication → Disabled**. После этого
`python scripts/check_live.py` обязан пройти целиком.

Живая ссылка — одно из двух допустимых подтверждений работающего MVP.
Стена авторизации на ней стоит дороже любых недоделок интерфейса, потому
что она отменяет само подтверждение.

### Если карта серая

Значит не загрузились тайлы подложки. Смотреть консоль браузера: CSP в
`vercel.json` разрешает ровно два хоста — `tile.openstreetmap.org` и
`server.arcgisonline.com`. Если в коде появился третий, его нужно добавить
в `img-src`, иначе браузер молча заблокирует запросы.

### GitHub Pages — запасной аэродром

[`.github/workflows/pages.yml`](../.github/workflows/pages.yml) собирает
сайт на каждый push в `main` и публикует его, **если Pages включён**.
Пока не включён, сборка и проверки всё равно идут, а шаг публикации
пропускается без ошибки: красный значок должен означать поломку, а не
ненастроенную кнопку.

Включить — одно действие: **Settings → Pages → Source: GitHub Actions**.
Адрес получится `https://k41270075-stack.github.io/hakathon/`; `base: './'`
в конфиге Vite уже рассчитан на подкаталог, менять ничего не нужно.

Держать два адреса одновременно опасно тем, что они расходятся. Поэтому
правило простое: **в деке и README печатается ровно один адрес — тот, на
котором `check_live.py` прошёл.** Второй остаётся запасным и в материалы
не попадает.

## 2. Telegram-бот

### Шаг 1. Создать бота — только вы

1. Открыть Telegram, найти **@BotFather**
2. Отправить `/newbot`
3. Придумать имя (например `VANTAGE Астана`) и username
   (например `vantage_astana_bot` — должен заканчиваться на `bot`)
4. BotFather пришлёт токен вида `7123456789:AAF...` — **это пароль,
   никому не показывайте и не коммитьте в репозиторий**

### Шаг 2. Вшить имя в сайт

Пока имя не задано, `citizen.html` показывает инструкцию вместо кнопки и
QR. Это намеренно: кнопка на несуществующего бота хуже, чем её отсутствие —
на защите она открывается в пустоту при полном зале.

```powershell
python scripts/make_bot_qr.py @vantage_astana_bot
git add web-next/public/data/site.json web-next/public/bot-qr.svg
git commit -m "feat: подключить бота к сайту"
git push
```

Скрипт пишет `site.json` и рисует QR. Vercel пересоберёт сайт сам —
на странице появятся кнопка, QR и username.

Токен сюда не попадает и попасть не может: скрипт принимает **имя**, а не
токен. Имя публично, токен — нет.

### Шаг 3. Узнать свой chat_id

Нужен, чтобы бот присылал оповещения о новых объектах.
Напишите **@userinfobot** — он ответит вашим числовым id.

### Шаг 4. Проверить локально

```powershell
$env:PYTHONUTF8 = "1"
$env:VANTAGE_BOT_TOKEN = "токен от BotFather"
$env:VANTAGE_BOT_SALT = "любая длинная случайная строка"
$env:VANTAGE_BOT_SUBSCRIBERS = "ваш chat_id"
.venv\Scripts\python.exe -m vantage.bot
```

Напишите боту `/start` — он должен ответить. Работает, пока открыто окно.

Это стоит сделать до сервера: если что-то не так с токеном, здесь видно
сразу, а в контейнере придётся читать логи.

### Шаг 5. Поднять на Vercel — бесплатно и без карты

Локальный запуск умирает вместе с ноутбуком. Для постоянной работы бот
живёт бессерверной функцией на том же Vercel, где стоит сайт:
[`api/telegram.py`](../api/telegram.py).

**Почему не Fly.io.** Бот в `vantage.bot` работает на long polling — сам
ходит в Telegram за обновлениями, и ему нужна машина, которая не спит.
Бесплатные хостинги усыпляют контейнер без входящих запросов; Fly машину
даёт, но бесплатный тариф там убрали и нужна карта.

Webhook снимает вопрос: Telegram сам присылает обновление на адрес, и
между сообщениями машина не нужна вовсе. Функция существует ровно во
время запроса. Ни нового сервиса, ни карты, ни отдельного счёта.

**1. Обновить указатель объектов** (после каждого прогона):

```powershell
python scripts/make_bot_index.py
git add api/candidates.json
git commit -m "data: указатель объектов для бота"
git push
```

**2. Задать переменные в Vercel** — Settings → Environment Variables,
все четыре, для Production:

| Переменная | Что положить |
|---|---|
| `VANTAGE_BOT_TOKEN` | токен от @BotFather |
| `VANTAGE_BOT_SECRET` | любая длинная случайная строка |
| `VANTAGE_BOT_SUBSCRIBERS` | ваш chat_id от @userinfobot, несколько — через запятую |
| `VANTAGE_BOT_SALT` | ещё одна случайная строка |

В токен можно вставить хоть всё поздравительное сообщение BotFather
целиком — функция выковырнет из него ключ сама. В секрет можно писать что
угодно, включая кириллицу и пробелы: в Telegram уходит не он, а его
отпечаток.

**Переменные читаются функцией из той сборки, при которой существовали.**
Поменяли переменную — нужен новый деплой, иначе функция продолжит работать
со старым значением. Проще всего сделать любой `git push`; в интерфейсе:
Deployments → у верхней записи **⋯** → **Redeploy**.

**3. Зарегистрировать вебхук.** Один раз, открыть в браузере:

```
https://ваш-адрес.vercel.app/api/telegram?action=set
```

Ни токен, ни секрет подставлять не надо — они уже у функции. Страница
ответит «Регистрация вебхука на …: успешно» и покажет состояние.

Напишите боту `/start` — он ответит.

### Если бот молчит

Откройте адрес функции **без параметров**:

```
https://ваш-адрес.vercel.app/api/telegram
```

Страница показывает всё, что нужно для разбора: заданы ли переменные, на
какой адрес зарегистрирован вебхук, сколько обновлений скопилось и что
Telegram ответил последней ошибкой. Токен из вывода вырезается — страница
публичная.

Три случая выглядят снаружи одинаково, а лечатся по-разному:

| Что видно | Что делать |
|---|---|
| `Вебхук: НЕ ЗАРЕГИСТРИРОВАН` | открыть `?action=set` |
| `Токен задан: НЕТ` | переменная не дошла — нужен Redeploy |
| `Последняя ошибка:` с текстом | текст и есть причина, читать его |

**Чего у бессерверного бота нет.** Антиспама между вызовами и журнала
сообщений: функция не помнит ничего между запросами, а поднимать базу
ради счётчика — менять одну зависимость на другую. В `/stats` про это
сказано прямо. Если понадобится журнал — это Vercel KV или любая внешняя
база, но для защиты незачем.

### Что бот умеет сразу

- `/start`, `/help`, `/stats`
- принимает геолокацию и фото от жителей
- сверяет точку с найденными объектами: совпало — подтверждение,
  не совпало — новый объект, которого спутник не увидел
- рассылает оповещения подписчикам
- ограничивает спам: 10 сообщений в сутки, 30 секунд между ними
- не хранит идентификатор отправителя, только хеш с солью

## 3. API (опционально, подумайте дважды)

API отдаёт **точные координаты и суммы ущерба** — адресные данные.
Публиковать его в интернет до защиты незачем: жюри смотрит карту и
репозиторий, а адресные данные в открытом доступе создают ровно ту
проблему, от которой мы защищались ролевым доступом.

Сайту он не нужен: кнопка «Черновик акта» собирает документ в браузере из
тех же полей, что показаны в карточке, и отправляет в печать.

Если всё же нужен:

```bash
cd deploy
fly launch --no-deploy --name vantage-api --dockerfile Dockerfile
fly secrets set VANTAGE_API_TOKENS="длинный-случайный-токен:akimat"
fly deploy --build-target api
```

Токены должны быть длинными и случайными. Не `test123`.

## Чек-лист перед защитой

- [ ] `python scripts/check_live.py` проходит целиком — это единственная
      проверка, которую нельзя пройти по ошибке из залогиненного браузера
- [ ] Ссылка открывается **в окне инкогнито** и **с телефона**, а не
      только с ноутбука
- [ ] Адрес в деке и в README — тот самый, который прошёл проверку
- [ ] На карте данные настоящего прогона, красной полосы нет
- [ ] Бот отвечает на `/start` **с чужого телефона**
- [ ] Оповещение о сообщении жителя доходит до вашего Telegram
- [ ] QR на `citizen.html` сканируется с экрана проектора, а не только
      с монитора в упор
- [ ] Записан дубль демонстрации на видео на случай отказа всего сразу

Последний пункт не перестраховка. Wi-Fi в зале общий на всех участников, и
проверять его работоспособность впервые во время своей защиты — плохая
идея.
